### V7 — Difficulty Invariance (Encoder Invariance)

```
V7. Difficulty Invariance (Encoder Invariance): The D_hard curriculum
    produced by V6 routing is world-grounded. The geometric signature
    of a high-divergence failure class persists across encoder upgrades
    — difficulty is a property of the input, not of the encoder version.
    An input that is D_hard under encoder generation t remains D_hard
    under generation t+1 (up to threshold rescaling).

    Proved in: DOI 10.5281/zenodo.20614051
    (The Encoder Is Not the Memory, Sajeev 2026).

    Architectural consequence: the adapter router's centroid-match step
    (System 1) must not apply a temporal trust gate — failure-class
    geometry is durable regardless of when the adapter was trained or
    which encoder version produced the stored centroids.
```

## Architectural Significance

V7 closes the contract between the routing layer and the memory layer.

The key consequence: `AbstractAdapterRouter._nearest()` (System 1 — centroid
identification) is formally **trust-invariant** — it must never apply a temporal
gate. The prohibition on temporal gating in System 1 is now an architectural
consequence of V7, not a design preference.

This means adapter libraries do **not** need to be rebuilt when encoder weights
improve. Failure-class geometry is world-grounded, not encoder-version-specific.
Only System 2 (LoRA correction) is perishable and subject to the temporal trust
gate `W = exp(−λ · Δt)`.

The complete routing contract is now:

```
AbstractModalEncoder → AbstractDivergenceRouter (V1–V7) → AbstractDMN → AbstractAdapterRouter
                                                   ↓
                                    D_hard queue (world-grounded, encoder-invariant)
```
